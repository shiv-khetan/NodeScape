Docs

Install NodeScape, add a server, and learn what each part does. The app needs nothing on the server beyond standard Linux tools and your SSH login.

Install

Download the Windows installer from the latest release and run it.

Windows needs Microsoft Edge WebView2 Runtime and the OpenSSH client available to your account.

Add a server

Open NodeScape. The environment check locates system SSH and ssh-keygen.

  1. Choose an alias from an existing SSH config, or use the New server form.

    For a new server, enter a server name, alias, hostname or IP address, port, and SSH user. Choose SSH key or Password for authentication. For SSH key authentication, you can choose an existing key, enter a new key path, or generate a key.

    Under Advanced, you can add a jump host, written as user@bastion.example:22. One hop is supported, and the jump host never receives your password.

  2. Compare the host fingerprint with a trusted source. Approve first contact in the OpenSSH prompt only after checking it. Investigate a changed key with the administrator.
  3. Optionally install a public key through the guided terminal.
  4. Test the connection and save the server.

Password login and remembered passwords

Enter the server login password when connecting. You can select “Remember on this computer” to save it encrypted in Windows Credential Manager. It uses Local persistence and does not roam.

The password is never written to the SSH config. NodeScape forgets it if the server refuses it or you remove the server.

Processes running as the same Windows user can read Credential Manager and process environments. A remembered password is not protected from those processes.

Server health in the sidebar

With two or more saved servers, the sidebar shows server health. Statuses are healthy, N failed, unreachable, needs login, and host key.

Health is checked every two minutes. The current server’s status comes from its live snapshot.

Admin actions and sudo

Before an admin action, the confirmation dialog shows Server, Scope, and whether it requires an administrator password. When needed, NodeScape asks for your sudo password for that action. It uses the password once and never stores it.

The admin note reports one of these states:

  • “Admin actions ask for your sudo password”
  • “Admin actions run with passwordless sudo”
  • “This account isn’t in a sudo group, so admin actions will likely be refused”
  • “sudo isn’t installed on this server, so admin actions are unavailable”

Actions on ssh, tailscaled, network, and firewall units can affect your access. The lockout warning requires you to confirm “I have another way into <server>”.

Connection problems

Choose “Show details” to run ssh -v and view the client log with the password removed.

Error shown What it means What to do
Password required The server accepts password login, and no password is held for this server. Choose “Enter password” and enter the login password.
Password refused The server refused the password. NodeScape has forgotten it. Enter the password again.
Unreachable or timed out Name resolution or the network connection failed, or the operation timed out. Check the network or Tailscale connection to the server, then choose Retry.
Connection closed The server closed or reset the connection. Connection limits, fail2ban, or an sshd restart may be responsible. Check the server and retry.
Host key not trusted or changed The host key is not trusted, or it differs from the trusted key. Compare the fingerprint with a trusted source before approving first contact. Investigate a changed key with the administrator.
Authentication failed (key) SSH authentication failed. Check the SSH user and key configuration, then retry. Use “Show details” to inspect the client log.

Build from source and run tests

Install Node.js 22+, stable Rust, and the platform’s Tauri build prerequisites. On Windows, these include Visual Studio C++ Build Tools, the Windows SDK, and WebView2.

On Ubuntu, install the required packages:

sudo apt-get install build-essential libwebkit2gtk-4.1-dev libssl-dev libxdo-dev librsvg2-dev libayatana-appindicator3-dev patchelf

From your checkout, run:

npm ci
npm run dev
npm run build

The build scans the shipping frontend, then places installers in src-tauri/target/release/bundle/. Review release contents as well.

Run the tests:

npx playwright install chromium
npm test
npm run test:rust
npm run check:release
npm run test:app

npm test uses a local HTTP server and synthetic fixtures. npm run test:app is a separate Windows and WebView2 test project.

For additional release checks, run:

cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings

Security model

  • System OpenSSH handles keys, agents, SSH config, and known hosts. Check fingerprints before approving first contact and investigate changed keys.
  • Login passwords can be remembered in Windows Credential Manager. Sudo passwords are requested per action and never stored.
  • NodeScape validates inputs and limits application commands. The interactive terminal permits remote shell use.
  • The local Windows account, SSH configuration, agent, and selected identity files are trusted.
  • There is no telemetry or cloud backend. The app can work without internet access when the SSH server is reachable.

For reporting guidance and threat boundaries, see SECURITY.md.
